## Current state

Published on 2026-10-30 under https://github.com/datubu. All ten repositories are public. All nine websites are deployed with GitHub Actions and GitHub Pages, bound to the domains below, with HTTPS enforcement enabled. Public HTML and data.json responses were verified on every domain; cross-site links use the custom domains.

## Upload order

1. Upload human-journeys, then journeys, then the eight website wrappers, all under the selected owner. Avoid creating autogenerated README commits in remote repositories before pushing existing local history.
2. Enable GitHub Actions as the Pages build source for each of the nine website repositories. No Pages site is needed for human-journeys.
3. Run deploy.yml for each website and check its actual Actions result. The website workflows can read public content and engine repositories with their regular read-only checkout permissions.
4. Before custom domains are ready, the default network mode links to `https://OWNER.github.io/REPOSITORY/`. All paths, nested story assets, manifests and service-worker scopes work under repository subpaths.
5. Configure each custom domain in the corresponding repository's Pages settings, then configure DNS. Do not treat a generated CNAME file as a substitute for Pages settings when using GitHub Actions.
6. Once all hostname bindings are ready, set CUSTOM_DOMAINS_ACTIVE=true in all website repositories and rebuild. Links then use datubu.com and the eight agreed subdomains. HTTPS enforcement is enabled after certificate readiness is confirmed.

## Automatic content updates

The content repository checks bilingual pairs, IDs, source references, chapter order and geometry when a PR or main-branch update runs. After a successful main push, it can dispatch builds to all nine website repositories with the exact content commit SHA.

Cross-repository dispatch requires PAGES_DISPATCH_TOKEN in the content repository's Actions secrets, scoped to dispatch access on the nine website repositories. A GitHub App installation token or appropriately scoped token can supply it. The normal GITHUB_TOKEN is scoped to its own repository. With no dispatch credential, content checks still run and clearly report that site workflows should be triggered manually. Do not put a token in Markdown, site.config.json, Git remotes or committed workflow values.

Current deployment: no cross-repository dispatch credential is stored. After a content update passes checks, manually run the Deploy workflow in each affected website repository. Ordinary website pushes deploy that website automatically. CUSTOM_DOMAINS_ACTIVE is already true on all nine website repositories.

Website workflows accept CONTENT_REF and ENGINE_REF repository variables to pin content and shared code versions. On every run, the resolved Git commit SHAs are recorded in build-info.json. Initial defaults are main; release tags or full SHAs can be pinned when publishing a release. Changes to shared code require a new build of each affected website (manual workflow_dispatch or a dispatch batch).

## DNS plan

For the eight subdomains, use CNAME records pointing to `OWNER.github.io` (not a repository URL). Bind each hostname to its correct repository in Pages settings. Configure the apex datubu.com according to GitHub's current documented apex instructions at publication time; the prepared tool does not modify DNS. The www alias, if desired, should be configured consistently with the main-site domain.

## Local review

Run `npm ci`, `npm run build:all`, `npm run check`, `npm run preview` in journeys. Run `python scripts/publish-github.py --plan` for a read-only local repository/domain plan. The publisher takes credentials only from GITHUB_TOKEN and requires an explicit --upload flag before any network mutation. It refuses pre-existing non-empty repositories and never force-pushes. Custom-domain binding is a separate operation after DNS preparation.

## Product limits

The geography is a regional schematic, not surveyed ancient paths. The walk destination provides official heritage references, not a verified hiking itinerary. Local bookmarks and progress are browser-local; standalone subdomains do not have unified sign-in or synchronized saved data. All satellite/terrain layers require network access. Offline caching covers the local app shell and compiled text, not the earth imagery.
